# 17.2 判别式 PRM

17.1 节的证明在第六步漏了一个平方。要让模型识别这类错误，最直接的办法是收集许多“题目—推理前缀—当前步骤”，请标注员判断当前步骤能否继续。训练完成后，评价器看到新步骤，就输出 good、bad 或 neutral 的概率。

这就是判别式 PRM：把逐步检查改写成分类任务。本节沿着一条数据生产线展开——先把完整推理切成可标注步骤，再训练分类器，然后把步骤概率用于候选排序或 RL，最后回头检查标注噪声和步骤边界会怎样改变结果。

## 1. 如何收集过程监督数据

分类器需要先看到带标签的步骤。以 17.1 的证明为例，标注员读取题目和前五步，再判断第六步的等式变换是否成立。只展示当前一句会丢失前提，展示整条后续推理又可能让最终答案影响判断，因此输入通常截止到当前步骤。

[Let's Verify Step by Step](https://arxiv.org/abs/2305.20050)（Lightman et al. 2023）比较了只标最终答案和逐步标注两种路线。差别不在模型是否“更大”，而在监督信号落在结尾还是每一个步骤。

论文比较两种监督位置：

| 监督方式              | 标注内容         | 标注成本                 |
| --------------------- | ---------------- | ------------------------ |
| **ORM**（Outcome RM） | 最终答案对错     | 一条解答一个结果标签     |
| **PRM**（Process RM） | 中间步骤能否成立 | 一条解答包含多个步骤标签 |

两类评价器都用来给模型生成的候选解排序。论文发现，随着模型和标注规模增大，过程监督在给定实验中持续优于结果监督；使用完整数据训练的过程监督模型在一个有代表性的 MATH 测试子集上解决了 78% 的问题。这里的 78% 包含多候选生成与评价器选择，不能当成单次生成准确率，也不能直接外推到其他任务。

### 1.1 PRM800K 怎样记录步骤标签

[PRM800K](https://github.com/openai/prm800k) 是 OpenAI 公开的步骤级标注数据集。规模：

- **800K** 个步骤级标注
- 来自 MATH 数据集中题目的模型解题过程
- 每个步骤标注为三种状态之一：
  - **good**（正确）：推理合理，可以继续
  - **bad**（错误）：推理有误，应该停止或回退
  - **neutral**（中性）：可能是中间过渡，不评价对错

数据收集可以沿着一条解题轨迹逐步进行：

1. 让基座模型生成候选步骤或完整解题过程；
2. 把候选按数据规范组织成可独立判断的步骤；
3. 标注员结合原题和此前步骤给当前候选标记 $+1$、$0$ 或 $-1$；
4. 发现首个错误以后停止或改写后续候选，把容易混淆的样本留给下一轮主动学习。

仓库把这些值分别解释为正确、没有明显错误但未取得进展、错误。它们常被写成 good、neutral、bad，训练时仍要以数据字段和标注说明为准。

#### 从标注规模理解成本

OpenAI 没有公开 PRM800K 的实际标注费用。下面只用一个简化估算说明“80 万个步骤”意味着多少工作量：

- 800K 步骤 × 平均 30 秒/步 = 24,000 小时（约 12 人年）
- 如果每步平均检查 30 秒，总工作量约为 24,000 小时

实际项目还要计算培训、复核、争议仲裁和质量抽检，因此不能把上述工时直接换算成 PRM800K 的真实成本。这里能够确定的是：逐步监督比只检查最终答案需要更多人工判断，团队必须把标注预算用在最容易出错、最能区分候选的步骤上。

## 2. 如何训练步骤分类器

有了步骤标签，下一步才是训练分类器。模型必须同时读取原题、此前推理和当前步骤，因为“所以 $p$ 是偶数”单独看没有意义，它是否成立取决于前面已经得到什么条件。

### 2.1 模型架构

分类器可以沿用语言模型读取长前缀的能力，再在当前步骤末尾输出类别或标量分数。输入包含 `<题目> <截至第 i 步的解答>`，输出表示当前步骤正确、错误或中性的概率。公开论文的重点是过程监督与结果监督的比较，不需要把未公开的专有基座猜成某个 GPT-4 版本。

后续工作（如 [Math-Shepherd](https://arxiv.org/abs/2312.08935)）也使用开源语言模型构造过程奖励。基座大小、评分头和标签来源可以变化，但分类器都必须读取当前步骤以前的上下文。

### 2.2 训练目标

对第 $i$ 个步骤，模型输出 good、bad、neutral 三个概率。训练用交叉熵提高人工标签对应类别的概率：

$$\mathcal{L}_{\text{PRM}} = -\sum_{i} \sum_{c \in \{good, bad, neutral\}} y_{i,c} \log p_\theta(c | q, o_{\leq i}, s_i)$$

其中 $c$ 遍历三个类别，$y_{i,c}$ 是 one-hot 标签，$p_\theta(c\mid q,o_{\le i},s_i)$ 是模型根据问题和截至当前步骤的上下文预测的类别概率。若第 $i$ 步标签是 good，求和中只有 good 对应的 $y_{i,c}=1$，这一项就变成 $-\log p_\theta(\text{good}\mid\cdots)$。模型给 good 的概率越接近 1，损失越小。

### 2.3 训练数据增强

人工标签有限时，可以从已有答案构造更多训练样本。常见做法包括：

- **自动标注**：用更强的评价模型或结果 rollout 估计未标注步骤，得到带噪声的银标签
- **合成数据**：从已知正确的解题过程中生成"看起来像错"的步骤作为负样本
- **数据混合**：把 PRM800K 和 Math-Shepherd 等其他数据集合并

## 3. 如何用于答案选择与 RL

分类器输出的是每一步的类别概率，系统还要决定怎样使用这些概率。推理时可以给多条完整解答排序，训练时则可以把步骤分数转成奖励。两种用法共享同一个 PRM，但聚合方式和风险不同。

最直接的用法是 **Re-ranking（重排序）**：先生成多条候选推理，再用步骤分数选择一条。它也可以提供训练奖励，但这还需要决定怎样把步骤分数转换成 token 或轨迹回报。

Re-ranking 的工作流程：

1. **生成**：让 base model 对一个数学题生成 N 个候选解（N 通常 4-64）
2. **打分**：用 PRM 给每个候选解的每一步打分，得到整条解题过程的总分
3. **选择**：选总分最高的候选解作为最终答案

PRM 在这里负责排序，并不替代生成模型。候选数量增加会提高至少出现一条正确解的机会，也会增加生成和打分成本；因此论文用 Best-of-$N$ 曲线比较 ORM 与 PRM，而不是把一个多候选结果写成单次模型准确率。在代表性的 MATH 子集上，完整过程监督模型在论文的大规模候选设置中达到 78%，并在不同候选预算下优于对应的结果监督模型。

### 3.1 Token 级与步骤级重排序

PRM Re-ranking 有两种打分方式：

**Token 级**：每个 token 一个分数，整条回答的总分 = 所有 token 分数的某种聚合（mean、sum、min）。

**步骤级**：每个推理步骤一个分数，整条回答的总分 = 所有步骤分数的某种聚合。

PRM800K 对应的是步骤级判断：评价器在每个步骤末尾给分，再把这些分数合成整条解答的排序依据。

聚合方式的选择：

- **Mean**：所有步骤的平均分。鲁棒，但可能稀释关键错误步骤的影响
- **Min**：所有步骤的最低分。保守，倾向于"任何一个步骤错了就否决整条"
- **Product**：所有步骤分数的乘积。比 min 更严格

在该数学实验中，最低步骤分数是有效的聚合方式，因为一个错误等式就可能破坏整条证明。开放写作没有同样严格的逻辑依赖，不能直接照搬这一选择；聚合规则应在目标任务的验证集上确定。

### 3.2 把步骤分数用于 RL 训练

Re-ranking 是 inference-time 应用。PRM 也可以用于 RL 训练——把 PRM 的步骤级分数作为 RL 的密集 reward。

具体做法：

```python
# 用 PRM 作为 RL 训练的 reward 函数
def prm_reward(prompt, response):
    # 切分 response 为推理步骤
    steps = split_into_steps(response)

    # 对每一步打分
    step_scores = [prm(prompt, steps[:i+1]) for i in range(len(steps))]

    # 聚合为整条 response 的 reward
    # 选择 min：任何一个步骤错了就否决
    return min(step_scores)
```

这个 reward 函数可以替代 RLHF 中的 ORM，用于 PPO / GRPO 训练。

[Math-Shepherd](https://arxiv.org/abs/2312.08935) 用自动构造的过程标签训练奖励模型，并把它用于候选选择和强化学习。具体增益取决于基础模型、数据集和采样设置，因此应在相同计算预算下与 ORM 比较。

## 4. 标注与步骤切分如何影响效果

到这里，PRM 的数据流已经完整：切步骤、标标签、训练分类器、聚合分数。风险也对应这四步。标注员可能误判，领域变化会让分类器失去知识，步骤切得太长或太短又会改变标签含义。

判别式 PRM 的效果受到以下条件限制：

### 4.1 标注成本

逐步标注需要阅读上下文、判断当前步骤并处理争议，成本明显高于只核对最终答案。新的代码或生物医学任务也不一定需要复制一个 PRM800K：可以先标少量高价值样本，测量分类器在哪些步骤失效，再决定是否扩大数据。

### 4.2 跨领域泛化

数学中的等式变换与代码中的状态修改需要不同知识，因此数学 PRM 不能未经评测就用于代码。迁移时要重新检查步骤切分、标签定义和分类准确率；必要时补充目标领域标签。

[生成式 PRM](./generative-prm)（下一节）可以用自然语言说明判断依据，较容易接入新任务，但这种接口并不保证它自然拥有更强的跨领域准确率。

### 4.3 标注噪声

即使有 PRM800K，标注也不是 100% 准确：

- 不同标注员对同一步骤可能判断不同
- 复杂推理步骤的对错本身就有主观性
- 中性（neutral）类别的边界模糊

可以用重复标注、争议复核和模型集成降低单个标签或单个评价器的影响。

### 4.4 步骤切分

判别式 PRM 需要把回答切分为"步骤"——但怎么切分本身是个问题：

- 按换行符切：太机械，一个"步骤"可能跨多行
- 按句号切：太碎，一个完整推理可能包含多个句号
- 用 LLM 切：引入新的 LLM 调用成本

步骤太短时，分类器看不到完整操作；步骤太长时，一个标签会覆盖多个判断。切分规则应与任务中的可验证动作对应，并作为数据规范的一部分固定下来。

### 4.5 怎样组合过程分数与结果分数

公开论文支持的做法可以归纳为三类。第一类同时保留 ORM 和 PRM：结果分数防止模型只写出“看起来合理”的过程，步骤分数负责定位中间错误。第二类按领域训练或校准评价器，使标签含义与数学、代码或工具任务一致。第三类先用强模型或规则生成候选标签，再由人工抽检困难样本。

如果把两类奖励加权，可以写成：

$$r = \alpha r_{\text{process}} + \beta r_{\text{outcome}}$$

$r_{\text{process}}$ 是步骤分数的聚合，$r_{\text{outcome}}$ 是最终结果，$\alpha$ 和 $\beta$ 控制两者权重。这个式子没有规定最佳权重；它提醒我们分别监控“过程分变高”和“任务是否真的完成”，避免评价器偏差被策略放大。

## 小结

判别式 PRM 把问题和推理前缀映射为步骤类别概率。数据生产依次经过步骤切分、人工或自动标注、分类训练和分数聚合；任何一处定义变化，最终排序和训练奖励都会变化。

它适合步骤边界明确、需要快速评价大量候选的任务。逐步标注和领域迁移仍然昂贵，[17.3 生成式 PRM](./generative-prm) 因此改用自然语言评价，让系统在给出结论的同时说明错误位置。
