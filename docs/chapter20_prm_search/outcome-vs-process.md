# 17.1 结果奖励与过程奖励

第 16 章让模型拥有更长的推理链和更大的推理预算。轨迹一变长，训练端就会遇到新的困难。假设模型先选对公式，中间抄错一个符号，最后答案错误；结果验证器只能返回 0，无法告诉模型前半段应当保留、错误从哪一步开始。

同一问题也出现在代码和 Agent 任务中。程序没有通过测试时，原因可能是第一次定位文件就错了，也可能只是最后一行语法错误；十次工具调用没有完成任务时，前九步的价值不能由结尾一个分数直接区分。

奖励只在序列末尾出现，中间动作没有直接反馈，这就是**稀疏奖励问题**。**过程奖励模型（Process Reward Model, PRM）**把评价放到中间步骤，使训练系统能够定位错误，推理系统也能在错误继续扩散以前换一条路径。本节先从一段具体证明出发，再建立结果奖励与过程奖励的数学形式，最后说明什么任务值得付出逐步评价的成本。

## 1. 最终奖励为什么不够

先延续第 16 章的数学模型。模型写出九步证明，最后结论恰好正确。结果验证器记为 1，训练系统于是提高整条回答的概率。可是第六步漏了一个平方，后面又碰巧回到正确结论。只看结尾，系统会把错误步骤和正确步骤一起强化。

### 1.1 先区分“答对”和“推对”

Outcome reward 只评价任务结果，类似考试只记录最终答案：答案正确记 1，错误记 0。它便宜、稳定，也适合数学答案、单元测试和规则检查。

Process reward 评价中间步骤，类似批改解题过程。它可以指出哪一步仍可继续、哪一步已经破坏前提。PRM 负责评价，Policy 负责生成；评价信号可以用于训练，也可以在推理时选择路径，但不会代替 Policy 完成答案。

二者解决的问题不同。结果奖励判断“整件事是否完成”，过程奖励判断“任务进行到这里是否仍在正确方向”。短回答通常只需要前者，轨迹越长，后者越有价值。

### 1.2 本章沿着同一条错误轨迹推进

后面五节都处理“第六步出错”这个问题，只是检查方式逐步变化：

| 小节                 | 使用的反馈                | 要解决的问题                         |
| -------------------- | ------------------------- | ------------------------------------ |
| 17.2 判别式 PRM      | good / bad / neutral 概率 | 怎样快速给大量步骤打分               |
| 17.3 生成式 PRM      | 自然语言检查与结论        | 怎样说明错在哪里并减少人工标签       |
| 17.4 形式化 Verifier | 证明检查器的通过或失败    | 怎样在可形式化任务中获得确定反馈     |
| 17.5 推理时搜索      | 中间节点分数              | 怎样在错误扩大以前回退并尝试别的路径 |
| 17.6 并行推理        | 多条完整路径与协调器      | 怎样比较不同解法并汇总最终答案       |

[第 13 章 RLHF](../chapter15_rlhf/standard-rlhf-pipeline)提供了结果奖励模型基础，[第 15 章 GRPO](../chapter18_grpo/grpo-family)说明了结果奖励怎样变成策略更新。第 17 章增加的是中间反馈；后面的 [Agentic RL](../chapter22_agentic/overview) 会把同一问题扩展到工具动作和环境状态，[奖励黑客](../chapter30_alignment_failures/classical-failures)则讨论评价器本身被利用时会发生什么。

### 1.3 从一个结尾分数走向逐步反馈

最终奖励只有一个分数，过程奖励需要先决定“什么算一步”。数学证明可以按等式变换切分，代码任务可以按编辑、编译和测试切分，Agent 任务则可以按一次工具调用切分。步骤边界确定以后，评价器才能把分数放在具体位置。

下面用一段证明观察：最终结论正确时，中间错误怎样被结果奖励漏掉。

### 1.4 稀疏奖励怎样掩盖中间错误

考虑一个具体的例子：让模型证明"√2 是无理数"。

模型生成的 CoT 长这样（简化版）：

```text
Step 1: 假设 √2 = p/q，其中 p, q 互质
Step 2: 那么 2 = p²/q²，即 p² = 2q²
Step 3: 所以 p² 是偶数
Step 4: 所以 p 是偶数（这一步用了"偶数的平方是偶数"的逆否命题）
Step 5: 设 p = 2k
Step 6: 代入：4k² = 2q²，即 2k² = q²
Step 7: 所以 q² 是偶数，q 也是偶数
Step 8: 这与 p, q 互质矛盾
Step 9: 所以 √2 是无理数  ✓
```

假设这个证明在 Step 6 出错了——比如写成"4k² = 2q²，即 4k = q²"（漏了平方）。最终结论"√2 是无理数"还是对的（结论正确），但推理过程有错。

若结果验证器只核对“√2 是无理数”这个结论，整条回答仍会得到 $r=1$。训练时，第 1—5 步的正确前缀、第 6 步的错误变换和后面的正确结论共享同一个回报。模型既不知道第 6 步应被抑制，也无法判断前面的定义和等式应当保留。

这就是稀疏奖励带来的归因困难：一条很长的轨迹只在结尾收到一个分数，结果碰巧正确时，错误步骤也可能随整条轨迹一起被强化。过程奖励要补充的正是“错误第一次出现在哪里”这一信息。

## 2. 如何把奖励分配到中间步骤

稀疏奖励问题在 RL 里有一个更正式的名字：**信用分配问题（credit assignment problem）**。

给定一个序列决策任务，最终奖励为 $r_T$，信用分配要回答怎样把这个结果传回 $a_1,a_2,\ldots,a_T$：哪些动作促成成功，哪些动作引入错误。

经典 RL 用几个方法解决这个问题：

### 2.1 折扣回报

把未来 reward 折扣到现在：

$$G_t = r_t + \gamma r_{t+1} + \gamma^2 r_{t+2} + \ldots + \gamma^{T-t} r_T$$

这里 $G_t$ 是从第 $t$ 步开始的折扣回报，$r_t$ 是当前奖励，$\gamma\in[0,1]$ 是折扣因子。若只有结尾奖励 $r_T=1$，第 $t$ 步得到的回报就是 $\gamma^{T-t}$；离结尾越远，权重越小。这在许多控制任务中合理，但证明中的早期定义可能决定后面所有步骤，单按距离衰减未必能准确表示它的责任。

### 2.2 GAE

[第 8 章 PPO 的 GAE](../chapter10_ppo/gae-reward-model) 通过引入 $\lambda$ 参数，在偏差和方差之间做权衡。GAE 需要价值函数；GRPO 省略了价值函数，因此必须用组内比较或其他反馈构造优势。

### 2.3 Token-Level Loss

[DAPO](../chapter18_grpo/deepseek-dapo) 把损失计算到 token 级，但监督信号仍来自整条回答的结果奖励。每个 token 因此获得了不同的梯度权重，却没有独立 verifier 判断“这一步是否正确”。它与步骤级 PRM 仍有区别。

### 2.4 PRM

PRM 训练一个独立的 verifier，对每一步推理打分。与结尾的单个结果奖励相比，它提供更密集的反馈，使系统能够比较具体步骤。

## 3. Outcome Reward 与 Process Reward 有何区别

前面的证明已经说明直觉差别，下面用输入和输出把两类评价器写清楚。

### 3.1 Outcome Reward Model

ORM 接受一个 prompt $q$ 和一个完整回答 $o$，输出一个标量分数：

$$\text{ORM}(q, o) \in \mathbb{R}$$

$q$ 是问题，$o$ 是完整回答，输出是一个标量。在数学任务里可以直接取 0 或 1；开放任务也可以由奖励模型输出连续分数。无论哪种形式，整条回答只有一个结果。

ORM 训练数据形式：

```text
(prompt, response, final_correctness)
```

例：("证明 √2 是无理数", "<完整证明>", 1)

### 3.2 Process Reward Model

PRM 接受 prompt $q$、回答 $o$、和回答中的某个步骤位置 $i$，输出该步骤的分数：

$$\text{PRM}(q, o, i) \in \mathbb{R}$$

$i$ 表示要评价的步骤位置。相同问题和回答在不同 $i$ 上会得到不同分数，因此可以定位哪一步开始不可靠。在数学任务里，它可以是：

- 离散标签：$+1$（正确）、$0$（中性）、$-1$（错误）
- 连续：[0, 1] 之间的概率

PRM 训练数据形式：

```text
(prompt, response, step_index, step_correctness)
```

例：("证明 √2 是无理数", "<完整证明>", 4, 1) # 第 4 步是正确的

### 3.3 两类奖励怎样进入 RL 训练

ORM 用于 RL 训练时：

$$r_{\text{ORM}} = \text{ORM}(q, o)$$

整个序列共享一个 reward。

PRM 用于 RL 训练时（一种常见做法）：

$$r_t = \text{PRM}(q, o, \text{step}(t))$$

每个 token $t$ 根据"它属于哪个推理步骤"获得对应的 PRM 分数。同一推理步骤内的 token 共享该步骤的分数。

这种做法把一个结尾奖励改成多个步骤奖励。若一个步骤包含多个 token，需要再决定这些 token 共享分数、只在步骤结尾接收分数，还是通过回报计算向前传播；PRM 分数不会自动变成“每个 token 都完全正确”的标签。

## 4. 什么时候需要过程奖励

推理链长并不自动意味着必须训练 PRM。先看任务能否可靠判断最终结果。数学答案可以代回原式，代码可以运行测试，棋局可以读取胜负；只要结果验证器准确、试错成本可接受，ORM 仍然能够训练出检查和修正行为。[DeepSeek-R1](https://arxiv.org/abs/2501.12948) 就展示了这一点：R1-Zero 主要依靠规则化的准确性奖励和格式奖励，也能在 RL 中逐渐形成更长的推理与自我检查。

过程奖励在另外一种情况下更有价值：最终结果只能告诉我们失败，却不能定位失败。可以依次检查三个条件：

1. 任务能否切出含义稳定的步骤，例如一次等式变换、一次代码修改或一次工具调用；
2. 中间错误是否会持续传播，使后面的生成和环境交互白白消耗预算；
3. 评价器能否比生成模型更可靠地判断当前步骤。

三个条件同时成立时，PRM 才可能抵消数据标注、模型推理和误判带来的成本。不同长度的任务可以这样理解：

| 任务情形                 | 只用 ORM 时会发生什么              | PRM 可能增加的价值         |
| ------------------------ | ---------------------------------- | -------------------------- |
| 几百 token 的短回答      | 错误位置离结尾很近，重新采样成本低 | 通常有限                   |
| 包含多次变换的证明或程序 | 最终失败无法说明哪一步应保留       | 定位首个错误，保留正确前缀 |
| 数千 token 的工具轨迹    | 早期错误会继续触发无效调用         | 及早停止、回退或换路       |

这里的 token 数只是任务规模示意，不能当作选择 PRM 的固定阈值。判断时要看步骤是否可定义、错误是否会传播，以及评价器是否足够可靠。

### 4.1 三类 PRM 怎样提供步骤反馈

确定需要中间反馈以后，还要选择反馈来自哪里。后面三节分别介绍分类模型、自然语言评价和形式化检查器。

#### 判别式 PRM

把 PRM 当作分类器：输入问题和截至当前步骤的推理，输出该步骤正确、错误或中性的概率。

代表工作：OpenAI 的 [Let's Verify Step by Step](https://arxiv.org/abs/2305.20050)（Lightman et al. 2023）。

训练数据：人工标注的步骤正确性（PRM800K 数据集）。

模型：编码器，或在 decoder-only LLM 上增加分类头。

#### 生成式 PRM

让 LLM 生成自然语言评价，再从评价中得到当前步骤能否继续以及错误原因。

代表工作：[ThinkPRM](https://arxiv.org/abs/2504.16828)（2025.04）。

训练数据：人工种子示例，以及模型扩展出的评价数据。

模型：可采用通用 LLM，通过提示或微调学习评价格式。

#### 形式化 PRM

把步骤翻译成 Lean、Coq 等形式语言，再交给证明检查器验证。

代表工作：DeepMind 的 [AlphaProof](https://deepmind.google/discover/blog/ai-solves-imo-problems-at-silver-medal-level/)（2024.07）、DeepSeek 的 [DeepSeek-Prover-V2](https://arxiv.org/abs/2504.21801)（2025.04）。

训练数据：形式化的数学定理（Lean4 格式）。

系统：负责生成形式化证明的模型，加上独立的证明检查器。

这三条路线是接下来三节的主题：[17.2 判别式 PRM](./discriminative-prm)、[17.3 生成式 PRM](./generative-prm)、[17.4 形式化 Verifier](./formal-prm)。

## 小结

结果奖励判断任务是否完成，过程奖励判断推理进行到某一步时是否仍可继续。任务越长、错误传播越昂贵，中间反馈越有帮助；如果最终结果容易验证，ORM 仍然可以成为主要训练信号。

过程反馈有三种常见来源：

- **判别式**：用步骤标签训练分类器，速度快，但依赖标注数据和领域覆盖；
- **生成式**：生成检查意见和结论，能解释错误，但评价本身也可能出错；
- **形式化**：由证明检查器给出确定的通过或失败，前提是任务和证明能够正确形式化。
