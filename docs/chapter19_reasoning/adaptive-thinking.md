# 16.5 自适应思考

16.4 节给模型增加了模式开关和思考预算，但开关仍要由用户或路由器设置。真实服务中的请求难度并不总能从表面判断：一道文字很短的数学题可能需要长证明，一份很长的会议记录却可能只需抽取日期。

自适应思考让模型根据任务和当前进展决定还要投入多少计算，系统再用硬上限控制最坏延迟。本节先建立连续预算的概念，再用研究型任务说明难度会在执行过程中变化，随后讨论成本与安全约束，最后说明这套机制为什么会连接到过程奖励和 Agent。

## 1. 模型如何判断任务难度

模型需要判断的并非一个固定“难度标签”，而是下一段计算是否仍有用。若当前证据已经足够，继续生成只会增加长度；若工具刚返回冲突结果，系统可能需要追加搜索和比较。连续预算用于描述这种逐步决定。

Hybrid Thinking 在“直接回答”和“进入思考”之间选择，自适应思考还要决定进入思考以后投入多少计算。为了描述这种连续变化，可以引入一个概念变量 $\tau\in[0,1]$。它用于本节解释，不代表所有产品都公开了同名参数：

- $\tau = 0$：直接回答
- $\tau = 0.5$：中等思考（几百 token CoT）
- $\tau = 1.0$：使用当前系统允许的最高推理预算

实现时不一定先显式输出 $\tau$。系统可以由路由器选择预算，也可以让模型通过停止生成的时机隐式决定计算量。$\tau$ 只把这些不同实现放到同一条“从低预算到高预算”的轴上。

### 1.1 自适应思考与 Thinking Budget 的区别

固定 thinking budget 由调用方给出 token 上限；自适应思考让模型根据请求决定是否进入扩展思考以及思考多久。调用方仍可通过 effort 档位影响模型倾向，并用 `max_tokens`、任务预算或超时控制最坏成本。

这两种方式各有优势：

- **thinking budget**：边界明确，便于预估单次成本，但每个请求都要使用预设预算；
- **adaptive thinking**：能跳过简单任务或延长复杂任务，成本分布更难预估。

实际部署通常让模型在允许范围内自适应停止，再用总 token、时间和工具次数设置硬边界。

### 1.2 从 Claude 的公开接口理解控制层

Anthropic 没有公开完整训练细节。根据 [官方博客](https://www.anthropic.com/news/claude-opus-4-6) 和 [Extended Thinking 文档](https://docs.anthropic.com/en/docs/build-with-claude/extended-thinking)，可以观察接口如何控制预算；内部是否使用独立难度评估器不能由接口直接确定。

#### 根据提示难度分配计算

要让模型按难度分配计算，训练信号需要同时反映答案质量与计算代价。例如可以把奖励写成

$$
r_{\text{total}}=r_{\text{task}}-\lambda C,
$$

其中 $r_{\text{task}}$ 衡量任务是否完成，$C$ 表示推理 token、工具调用或运行时间等成本，$\lambda$ 决定系统愿意用多少成本换取质量。这个式子没有规定具体训练算法，只说明两种压力怎样同时进入目标：

- 简单题思考太多 → 浪费算力 → 惩罚
- 难题思考太少 → 答错 → 惩罚

简单任务继续增加计算时，任务奖励不再明显上升，成本项会促使模型尽早停止；复杂任务中，只要额外计算能显著提高成功率，收益就可能超过成本。

#### Adaptive Thinking API

Claude 4.6 及后续支持模型使用 `thinking: {type: "adaptive"}`，并用 effort 调节模型使用扩展思考的倾向。下面是接口结构：

```python
# 启用 adaptive thinking
response = client.messages.create(
    model="claude-opus-4-6",
    max_tokens=16000,
    messages=[{"role": "user", "content": "..."}],
    thinking={"type": "adaptive"},
    output_config={"effort": "high"},
)
```

较早的 Extended Thinking 使用 `budget_tokens` 手动设置目标预算；在 4.6 上这套方式已经进入弃用流程，4.7 及以后改用 adaptive thinking 与 effort。接口演进恰好说明两层控制的区别：模型决定当前请求实际使用多少思考，开发者决定整体努力程度与资源上限。

#### Thinking Signatures

Claude API 的 thinking block 带有 `signature` 字段，用于验证并在多轮或工具调用中原样传回先前思考内容。某些被隐藏的思考会以加密内容返回，使 API 能在下一轮继续使用，而客户端不需要读取原文。签名的主要作用是保持上下文完整性，不能把它解释成“用户可见的推理结构”或自动安全过滤。

## 2. 自适应思考如何用于研究任务

一次数学问答通常在生成答案后结束，研究任务的难度却会随环境反馈变化：代码第一次运行失败、实验结果不支持假设、检索来源互相冲突，都会迫使模型重新分配计算。Anthropic 的模型评测包含缩小后的 AI 研究任务，可以用来理解预算为什么会在执行中变化。评测成绩依赖工具、运行时间和判分规范，不能直接换算成一般科研工作的效率。

### 2.1 LLM Training：实验结果决定下一步

模型先选择数据和训练配置，再写代码、运行小规模训练并读取 loss 与评测结果。若 loss 直接发散，下一份计算应当用于检查数据、学习率和数值设置；若训练正常但两个方案差距很小，系统可能需要增加样本或设计更能区分假设的实验。预算由观测结果逐轮调整，无法只根据最初提示的长度确定。

### 2.2 Text-RL：奖励上升不等于任务完成

文本环境要求模型定义状态、动作和奖励，再实现算法并比较策略。训练曲线上升以后，还要检查代理是否真的完成任务，还是只利用了奖励规则的漏洞。出现后者时，继续沿用同一奖励训练没有意义；计算应转向失败样本、奖励修改和重新评测。

### 2.3 Quadruped-RL：仿真反馈改变搜索方向

四足控制需要设置步态目标、动作惩罚和稳定性约束，再运行仿真观察策略。机器人虽然前进却频繁摔倒，说明速度奖励压过了稳定性；动作平稳但原地不动，则说明约束过强。每次仿真都为下一轮提供新的状态，因此预算还要覆盖代码修改、训练和行为检查，而不只是生成更长的文字。

三个任务共享一条过程：先做出可执行方案，读取环境反馈，再决定继续优化、修改目标还是停止。自适应思考在这里控制的是整条实验轨迹的计算与工具预算。

### 2.4 Constitution 怎样约束可观察行为

Anthropic 在 2026 年公开新版 [Claude Constitution](https://www.anthropic.com/news/claude-new-constitution)，说明希望模型遵循的价值与行为。它不直接公开模型每一步内部思考，却可以转化成训练样本、评价准则和外部测试。

#### Constitution 作为推理约束

Constitution 涵盖诚实、帮助性、安全以及不同相关方的利益。训练系统可以据此评价最终回答和可观察动作；如果系统保留推理摘要或工具日志，也可以检查其中是否出现规则冲突。隐藏的内部状态仍不能仅靠文档直接验证。

#### Constitution 怎样进入训练

Constitution 可以在训练阶段转成判断准则和偏好样本，不必在每次推理时完整放入提示：

1. 把 Constitution 拆解为可执行的判断准则
2. 用这些准则生成大量"宪法对齐"的偏好数据
3. 用这些数据做 RLHF / DPO 训练

这些样本提高符合准则的回答概率，但不能保证模型在所有新场景中都遵守准则，因此仍需独立安全评测。

#### Constitution 与可解释性

公开原则使外部评测者能够设计更具体的测试，例如在用户要求与安全规则冲突时检查模型怎样选择。它提高了行为目标的透明度，但原则、训练实现和实际行为仍是三个不同层次。

## 3. 如何控制安全、延迟与成本

让模型自行延长推理可以提高复杂任务的完成率，也会让一次请求的长度和工具次数更难预测。系统因此需要同时监控“额外计算有没有改善任务结果”和“最坏情况下会消耗多少资源”。

自适应思考把一次请求的长度和执行范围交给模型动态决定，因此下面三项约束要同时进入评测。

### 3.1 区分有效推理与无效长度

推理长度本身不等于推理质量。模型可能重复检查已经确定的结论，或生成与答案无关的文字；这会增加成本，却不提高成功率。

训练时可以把正确性与成本共同放入目标，部署时再比较增加预算前后的任务成功率。仅靠语言流畅度无法判断某段思考是否有用；需要结果验证器、消融实验或过程评价检查额外步骤是否改变了结论。

### 3.2 控制延迟与成本波动

同一条提示在不同采样中可能使用不同长度，因此延迟和成本会形成分布。服务需要记录中位数和尾部延迟，也要单独观察失败请求是否更容易耗尽预算。

部署时通常同时设置模型自主停止和硬预算上限。前者根据任务调整计算量，后者控制最坏情况下的延迟和费用。上限过小会截断难题推理，上限过大则使成本波动扩大。

### 3.3 处理推理链中的攻击面

工具结果和外部文档会不断进入长轨迹，其中可能包含与用户任务无关的指令。模型若把这些低优先级内容当成系统要求，后续搜索、文件访问和回答都可能偏离原任务。

这是 [OpenAI 的 Instruction Hierarchy](https://openai.com/index/the-instruction-hierarchy/)（2025）要解决的问题——明确系统 prompt、用户 prompt、工具返回结果的优先级，防止低优先级内容劫持高优先级行为。

### 3.4 比较固定、混合与自适应思考

三种控制方式的差别如下：

| 维度     | 固定预算               | 双模式                       | 自适应思考                           |
| -------- | ---------------------- | ---------------------------- | ------------------------------------ |
| 控制方式 | 每次请求使用预设预算   | 在直接回答与思考模式之间选择 | 模型在 effort 与硬上限内决定是否继续 |
| 优点     | 延迟与成本容易估计     | 简单任务可以跳过长思考       | 能随任务进展调整计算                 |
| 风险     | 简单题浪费、难题不足   | 路由错误会选错模式           | 成本波动，停止条件更难评测           |
| 适用场景 | 难度分布稳定的批量任务 | 通用对话与推理混合服务       | 研究、代码和长工具任务               |

从固定深度到 Hybrid Thinking，再到自适应思考，控制粒度逐步增加。粒度越细，越需要可靠的停止条件、成本监控和回归测试。

## 4. 如何接入过程对齐与 Agent

当模型只输出一个答案时，系统主要评价结尾；当模型在较长时间内自主思考和调用工具时，中间步骤也会影响成本与安全。自适应预算因此不能只看 token 数，还需要过程反馈判断哪些步骤值得继续。

### 4.1 过程对齐

过程奖励可以判断中间步骤是否正确、是否违反工具或安全约束。它比结尾奖励更早发现问题，但也要求评价器理解当前上下文。第 17 章将分别介绍三种反馈：

- PRM 对推理步骤打分；
- 监控模型检查长轨迹中的异常行为；
- 规则或 Constitution 把允许的动作写成训练与评测标准。

### 4.2 推理模型的安全沙箱

安全沙箱主要隔离工具、文件和网络权限。即使模型生成了错误计划，只要执行接口要求权限检查、参数校验和结果审计，错误文本就不会自动变成真实动作。推理内容是否向用户展示，则是 [16.6](./cot-visibility-alignment) 的问题。

### 4.3 推理 Scaling 的对齐

预算增加以后，监控成本也随轨迹长度和工具调用次数增加。评测不能只在固定短回答上进行，还要覆盖长上下文、预算耗尽、工具失败和中途恢复等条件。

### 4.4 推理与 Agentic 的融合

研究任务把推理与执行接在一起：模型写代码、运行实验、读取结果，再决定是否继续。此时思考预算还要和环境预算统一计算，例如最大工具次数、最长运行时间和允许重试次数。这正是 [Agentic RL](../chapter22_agentic/overview) 要处理的长轨迹决策。

## 小结

自适应思考把二值的模式选择扩展为连续的计算分配：模型根据任务决定推理深度，系统再用预算上限控制延迟和成本。研究任务说明这种机制可以覆盖较长的分析与执行过程，同时也使过程监控、提示注入防护和成本预测变得更重要。

[16.6 推理链的展示与对齐](./cot-visibility-alignment) 接着讨论一个直接问题：模型生成了内部推理以后，哪些内容应当展示，哪些内容需要监控或隐藏。
