# 17.3 生成式 PRM

17.2 的分类器看到错误等式后，只返回 `bad: 0.96`。这个分数适合排序，却没有告诉训练者究竟是平方丢了、前提用错了，还是当前步骤本身正确而前一步已经出错。换到代码、物理或新领域时，固定标签也很难暴露评价器缺少哪一部分知识。

生成式 PRM 让语言模型先写出检查过程，再给最终判断。例如它可以明确指出“从 $4k^2=2q^2$ 只能推出 $2k^2=q^2$，不能把 $k^2$ 改成 $k$”。自然语言解释让判断可检查，也复用了基座模型已有知识。

本节以 [ThinkPRM](https://arxiv.org/abs/2504.16828) 为例，先比较分类标签和生成式评价，再看少量种子数据怎样训练 verifier，随后分析增加验证计算的收益，最后说明什么情况下仍应使用更便宜的判别式 PRM 或结果奖励。

## 1. 如何生成自然语言评价

生成式评价仍然要完成和判别式 PRM 相同的任务：读取问题、推理前缀和当前步骤，判断这一步能否成立。变化在输出端——一个分类概率被替换为“检查依据 + 最终标签”。

### 1.1 判别式与生成式输出的差别

判别式 PRM（[OpenAI PRM800K](./discriminative-prm)）：

```text
输入：prompt + 第 i 步推理
输出：good / bad / neutral（三分类）
```

模型结构：读取完整前缀的语言模型 + 分类或打分头，最后输出类别概率。

生成式 PRM（ThinkPRM）：

```text
输入：prompt + 第 i 步推理 + "请评价这一步"
输出：自然语言的评价 + 最终判断
```

模型结构：标准 LLM（decoder-only），输出是文本。

### 1.2 生成式评价怎样复用已有能力

生成式 PRM 有两个可利用的条件：

**第一，复用 LLM 的预训练知识。**

判别式 PRM 需要训练分类头，并用步骤标签校准 good、bad、neutral 的边界。生成式 PRM 使用已经完成预训练的语言模型，模型可能已经掌握部分数学、代码和逻辑知识，微调主要教它按照统一格式检查步骤并给出结论。

**第二，自然语言可以保留判断依据。**

判别式 PRM 输出 good、bad 或 neutral，适合快速排序，却不会说明错在哪里。生成式 PRM 可以指出使用的规则、代入的数值和发生错误的位置，训练者因而能够检查判断是否可靠。

生成式 PRM 可以输出：“这一步想使用因式分解，但把 `x² - 1` 写成了 `(x-1)(x-2)`，正确形式应为 `(x-1)(x+1)`，因此当前步骤错误。”这类评价让训练者直接看到错误位置；是否把解释继续用作训练目标，还要由具体方法决定。

### 1.3 ThinkPRM 怎样构造训练数据

[ThinkPRM](https://arxiv.org/abs/2504.16828)（2025.04）从 PRM800K 的题目、解题前缀和人工步骤标签出发。标签仍然存在，但用途改变了：它们不直接训练一个分类头，而是筛选语言模型生成的检查过程。

#### 生成分步评价

训练样本要求模型逐步核对依据，并为每一步输出可抽取的正确或错误判断：

```text
Prompt: 评估以下推理的第 3 步：
问题：求方程 x² - 5x + 6 = 0 的解
推理：
  Step 1: 这是二次方程，可以用求根公式
  Step 2: 求根公式：x = (-b ± √(b²-4ac)) / 2a
  Step 3: 代入 a=1, b=-5, c=6，x = (5 ± √(25-24)) / 2 = (5 ± 1) / 2
  Step 4: x = 3 或 x = 2
请评估 Step 3。

ThinkPRM 输出：
让我检查 Step 3：
- a = 1, b = -5, c = 6 ✓（与原方程一致）
- 求根公式：x = (-b ± √(b²-4ac)) / 2a ✓
- 代入：x = (5 ± √((-5)² - 4·1·6)) / (2·1)
       = (5 ± √(25 - 24)) / 2
       = (5 ± √1) / 2
       = (5 ± 1) / 2 ✓
Step 3 是正确的。
判断：CORRECT
```

#### 生成、筛选再微调

数据构造按三步进行：

1. 用 QwQ-32B-Preview 为 PRM800K 中的解题前缀生成多条验证 CoT；
2. 只保留格式可解析、逐步判断与人工标签一致、长度不超过上限的样本；
3. 用保留的验证 CoT 微调 R1-Distill-Qwen 和 QwQ 等推理模型。

论文最终使用约 1,000 条验证 CoT，其中包含约 8,000 个步骤判断。为了得到这些样本，系统先生成约 5,000 条候选，再由 PRM800K 标签筛选。这里节省的是用于微调的过程标签规模，并没有完全取消高质量步骤标签；没有人工标签时，可以改用 rollout 估计银标签，但噪声也会进入筛选过程。

### 1.4 逐步评价与整条评价怎样选择

部署时可以每次只评价一个步骤，也可以把整条推理交给模型，让它依次输出各步判断。逐步评价始终把注意力放在一个边界清楚的动作上，容易定位首个错误，却需要多次模型调用；整条评价只需读取一次上下文，吞吐更高，但长轨迹中可能漏掉细小错误。

两种方式还可以组合：先用整条评价筛出低分轨迹，再对疑似出错的位置逐步复核。选择时应同时测量首错定位率、每条轨迹的 token 数和总延迟，不能只比较一次调用的速度。

## 2. 标签与验证计算如何影响效果

生成式 PRM 减少了微调所需的步骤标签，却增加了每次评价的生成成本。论文从三方面检查这笔交换是否值得。

### 2.1 少量过程标签能否训练有效评价器

ThinkPRM 使用约 8,000 个过程标签，约为论文判别式基线所用 712,000 个标签的 1%。在 ProcessBench、MATH-500 和 AIME 2024 的给定设置下，它在步骤验证、Best-of-N 和 verifier 引导搜索中超过同基座的判别式基线与未微调 LLM-as-a-Judge。这个结论依赖基座模型已经具备较强推理能力，也依赖人工标签对生成评价进行筛选。

### 2.2 数学训练能否迁移到科学与代码

论文还在 GPQA-Diamond 和 LiveCodeBench 的子集上测试领域迁移。相对使用完整 PRM800K 训练的判别式 verifier，ThinkPRM 分别高 8 和 4.5 个百分点。结果支持“生成式评价可以复用基座知识”，但评测只覆盖数据子集，进入新的代码库或科学领域前仍需重新校准。

### 2.3 Verifier 也可以增加推理计算

生成式 verifier 可以沿两条轴增加计算：并行采样多条验证 CoT 后聚合，或让同一条检查继续复核和修正。论文在相同 token 预算下比较了两者，整体差距不大，部分预算下并行方式略好；在 ProcessBench 子集上，ThinkPRM 相对未微调 LLM-as-a-Judge 高 7.2 个百分点。

这与 16.3 节的规律相同：更多验证计算只有在评价模型能够产生互补检查路径时才有用。若模型缺少领域知识，多次生成可能重复同一种误判。

## 3. 何时选择判别式或生成式 PRM

前面的结果说明生成式评价能够提高标签效率，但它不会在所有环节取代分类器。训练中需要每秒评价大量步骤时，生成一段解释可能太慢；研究和教育场景需要检查理由时，一个概率又不够。

| 维度         | 判别式 PRM               | 生成式 PRM                                   |
| ------------ | ------------------------ | -------------------------------------------- |
| 输出         | 步骤类别或概率           | 检查过程与可抽取判断                         |
| 单次评价     | 一次前向，吞吐较高       | 需要自回归生成，延迟较高                     |
| 数据         | 需要足够标签校准分类边界 | 仍需标签筛选生成评价，但可用较少样本微调     |
| 领域迁移     | 取决于训练覆盖与基座知识 | 可以在文本中调用基座知识，也可能生成流畅误判 |
| 增加验证计算 | 可用集成或多模型         | 可增加生成长度、复核轮数或并行样本           |
| 可检查性     | 只能观察分数与误差样本   | 能阅读判断依据，但依据不保证忠实或正确       |

### 3.1 任务规模与推理成本怎样影响选择

大规模 RL 每轮要评价大量步骤，通常先选吞吐更高的判别式模型；调试奖励、教育反馈或低频高价值任务需要查看错误原因时，生成式模型更合适。数据预算少并不等于推理预算少：生成式 PRM 可能节省标注，却在每次调用中使用更多 token。

### 3.2 混合两类 PRM

没有公开训练细节时，不应由产品输出反推内部是否使用生成式 PRM。公开方法足以支持三种组合：

1. **PRM 和 ORM 混合**：用 PRM 评估过程，用 ORM 评估结果，加权求和
2. **生成式 + 判别式混合**：生成式 PRM 提供高质量评价，蒸馏到判别式 PRM 用于大规模训练
3. **Self-PRM**：让模型自己评估自己的推理（与 [Self-Rewarding Language Models](https://arxiv.org/abs/2401.10020) 思路一致）

## 4. 过程奖励是否总是必要

即使 verifier 能逐步解释，系统仍要先问是否值得训练 PRM。答案容易自动验证、模型又能大量采样时，结果奖励也可能间接强化自我检查；步骤错误难以定位或采样预算有限时，过程反馈才更有优势。

[DeepSeek-R1](https://arxiv.org/abs/2501.12948) 提供了一个对照：R1-Zero 主要使用结果正确性与格式奖励，训练后仍观察到检查步骤和修改答案等行为。结果奖励会提高最终答对轨迹的概率；如果带有自检的轨迹更容易答对，这类行为也可能被间接强化。因此，PRM 是定位中间错误的一种方法，并非产生自检行为的唯一途径。

选择奖励方式时可以按反馈是否足够判断：答案容易自动验证、采样量充足时，结果奖励可能已经有效；长轨迹中间错误难以定位、训练预算有限时，PRM 能更早指出错误位置；跨领域使用时，还要单独评测 PRM 是否真的理解新领域。

因此，PRM 并非所有任务的必要条件；在训练预算有限或需要定位中间错误时，它仍能提供结果奖励缺少的反馈。

## 小结

ThinkPRM 在论文实验中用约 1% 的步骤标签达到与判别式 PRM 相近的结果，并保留了自然语言判断依据。这个优势需要与更高的推理成本一起考虑。

ThinkPRM 展示了怎样用自然语言评价减少逐步人工标注，并把判断依据保留给训练者检查。生成式 PRM 的可靠性仍受评价模型能力限制：评价模型不熟悉某个领域时，也可能给出看似完整但错误的解释。
