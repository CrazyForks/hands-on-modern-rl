# 17.4 形式化 Verifier

判别式 PRM 可能学到错误标签，生成式 PRM 也可能写出一段流畅但错误的检查。对 17.1 的平方错误，人类很容易判断；换成几十步的代数证明时，评价模型本身也可能算错。

若题目已经写成 Lean4、Coq 或 Isabelle 等形式语言，可以把候选证明交给证明检查器。检查器不根据“看起来是否合理”评分，而是验证每个证明项是否符合形式系统规则。这提供了更确定的反馈，也带来一个新的前置任务：自然语言题目必须先被正确形式化。

本节沿着“自然语言题目 → 形式命题 → 候选 tactic → 内核检查”这条线展开。先说明确定性来自哪里，再看 AlphaProof、AlphaGeometry 和 DeepSeek-Prover-V2 怎样搜索证明，最后讨论形式化范围、数据和计算成本。

## 1. 为什么形式检查能提供确定反馈

生成式 PRM 判断一句话是否合理，仍然依赖模型概率。形式检查器则要求候选证明构造出目标命题的证明项。先比较同一段证明在自然语言和 Lean4 中分别省略了什么。

### 1.1 形式化语言与自然语言的差别

数学证明可以用两种语言表达：

**自然语言**（informal）：

```text
证明 √2 是无理数：
假设 √2 = p/q，p 和 q 互质。
那么 p² = 2q²，所以 p 是偶数。
设 p = 2k，代入得 2k² = q²，所以 q 也是偶数。
这与 p, q 互质矛盾。所以 √2 是无理数。
```

人类容易阅读，但其中的“所以”常省略中间引理，符号含义也可能依赖上下文。

**形式化语言**（Lean4）：

```lean
theorem sqrt_two_irrational : Irrational (√2) := by
  intro h
  rcases h with ⟨p, q, h1, h2⟩
  -- 假设 √2 = p/q
  have h3 : p^2 = 2 * q^2 := by
    have : (√2)^2 = (p/q)^2 := by rw [h1]
    simp at this
    rw [div_pow] at this
    field_simp at this
    linarith
  -- ...
  sorry  -- (省略完整证明)
```

这段代码只用于展示语法，其中的 `sorry` 是“此处暂未给出证明”的占位符，不能算作完整验证结果。提交给 verifier 的证明需要去掉 `sorry`，并让 Lean 内核逐步检查每个 tactic 产生的证明项。检查通过表示：在当前公理、定理库和形式化命题下，证明项符合规则。它不能保证自然语言原题一定被翻译正确，也不能排除所选公理本身带来的假设。

### 1.2 Lean4 Verifier 的特点

Lean4 的几项特性使它适合提供过程反馈：

- **确定性检查**：在给定形式系统、公理和实现正确的前提下，通过检查表示证明满足规则
- **自动化**：编译过程是自动的，不需要人工判断
- **可扩展**：可以定义新的数学结构、新的定理
- **社区支持**：[Mathlib](https://github.com/leanprover-community/mathlib4) 已经形式化了大学水平的数学

### 1.3 形式化的适用边界

但形式化也有代价：

- **领域受限**：Lean4 主要用于数学。其他领域（自然语言推理、代码逻辑）没有成熟的形式化系统
- **数据稀缺**：Lean4 代码相对少，LLM 在 Lean4 上的预训练数据不足
- **门槛高**：写 Lean4 代码需要专门训练，大部分数学家不熟悉

## 2. AlphaProof 与 AlphaGeometry 如何搜索证明

证明检查器只能回答“这一步是否符合规则”，不会主动提出下一步。要自动解决新题，还需要策略模型生成 tactic、价值模型估计证明状态，并用搜索分配尝试次数。

2024 年 7 月，DeepMind 宣布 [AlphaProof 与 AlphaGeometry 2](https://deepmind.google/discover/blog/ai-solves-imo-problems-at-silver-medal-level/) 合计解决国际数学奥林匹克（IMO）2024 的 4 道题，分数达到银牌区间。AlphaProof 负责形式化代数和数论证明，AlphaGeometry 2 负责几何题。

### 2.1 AlphaProof 的架构

AlphaProof 把 AlphaZero 风格的强化学习、证明搜索与 Lean 检查连接起来：

```text
┌────────────────────────────────────────────────────┐
│ 1. 问题形式化：把数学题翻译成 Lean4                 │
│                                                    │
│ 2. AlphaZero 风格搜索：                            │
│    - 策略网络：推荐下一步 Lean4 tactic            │
│    - 价值网络：评估当前证明状态                    │
│    - 搜索算法：在候选 tactic 之间分配计算          │
│                                                    │
│ 3. Lean4 verifier：每个 tactic 自动验证           │
│                                                    │
│ 4. 自我博弈训练：用搜索结果训练策略和价值网络      │
└────────────────────────────────────────────────────┘
```

它沿用了 [AlphaGo Zero](https://www.nature.com/articles/nature24270) 的“策略提出动作、价值评估状态、搜索产生更好训练目标”结构。围棋中的动作是落子，形式证明中的动作是 tactic；证明状态、终止条件和数据生成方式仍然与棋局不同。

### 2.2 AlphaProof 怎样构造训练与搜索闭环

**设计一：构造形式化训练问题**

自然语言题目必须先变成 Lean 命题。训练阶段，DeepMind 用形式化器把约一百万道非形式化问题转换为形式问题，形成不同难度的训练库。IMO 2024 的六道正式赛题则由专家手工翻译，不能把训练数据自动形式化与比赛输入混为一谈。

形式化器可能误解量词、变量范围或隐含条件。Lean 只能检查“翻译后的命题是否被证明”，因此系统还要单独验证形式命题是否忠实对应原题。

**设计二：大规模 Lean4 训练**

训练库包含由自然语言问题自动转换的形式命题，以及搜索过程中产生的相关问题。AlphaProof 会尝试证明或证伪这些命题，把通过 Lean 检查的结果再用于更新策略。公开材料没有给出足以复现全部数据配比的细节。

**设计三：Lean 检查进入搜索循环**

每个节点对应当前证明状态，每个动作对应一个候选 tactic。Lean 检查器先淘汰不合法动作，完成证明的轨迹再成为强化学习信号。公开说明把这一过程描述为 AlphaZero 算法与证明搜索的结合，没有必要把它限定为某个未经披露的 MCTS 实现。

### 2.3 AlphaProof 的成绩

在 IMO 2024 的 6 道题中，AlphaProof 解决了两道代数题和一道数论题，AlphaGeometry 2 解决了一道几何题。两套系统合计得到 28 分（满分 42），达到当届银牌区间。剩余题目的失败可能发生在形式化、候选生成或搜索预算等不同环节，不能只由最终未通过判断是哪一环出了问题。

### 2.4 AlphaGeometry 怎样处理几何题

针对 AlphaProof 在几何上的弱点，DeepMind 发布了 [AlphaGeometry 2](https://www.nature.com/articles/s41586-024-07819-5)——专门解决几何题的形式化系统。

AlphaGeometry 2 把神经语言模型与符号推理引擎组合起来：语言模型提出辅助构造，符号系统进行演绎和检查。合成几何问题补充了训练数据，辅助线则让系统能够打开原本无法继续的证明路径。

在 IMO 2024 中，AlphaGeometry 2 在得到人工形式化的题目后，用 19 秒完成第 4 题。这个案例说明专用形式系统可以快速检查和组合几何关系，但自然语言到形式输入的转换仍在系统边界之外。

## 3. DeepSeek-Prover-V2 如何生成可检查证明

AlphaProof 说明搜索与检查器可以协作，开源工作还要回答训练数据怎样构造、复杂定理怎样拆分，以及二值通过信号怎样用于 RL。DeepSeek-Prover-V2 提供了另一套可检查实现。

[DeepSeek-Prover-V2](https://arxiv.org/abs/2504.21801)（2025.04）是 DeepSeek 开源的形式化 PRM 工作。它的目标是：

- 用 Lean4 + RL 训练一个能解数学竞赛题的开源模型
- 推进形式化 PRM 的工业可用性

### 3.1 Prover-V2 的方法

DeepSeek-Prover-V2 从自然语言证明草图开始，把复杂定理拆成较小子目标，再用专门证明模型逐个完成。

**改进一：递归证明搜索**

Prover-V2 用**递归定理证明**——把一个难定理分解为若干子目标，每个子目标再分解，直到子目标可以独立证明。

```text
主目标：证明 A
  ├── 子目标 1：证明 B（如果 B 成立，则 A 成立）
  │     ├── 子子目标 1.1：证明 C
  │     └── 子子目标 1.2：证明 D
  └── 子目标 2：证明 E
```

这种分解把一个长证明变成依赖关系清楚的小引理。前面的子目标可以成为后续子目标的前提，最后再把通过检查的局部证明合成为完整证明。

**改进二：binary reward**

Prover-V2 使用二值结果奖励：证明通过为 1，失败为 0。对同一个形式化命题和证明，Lean4 检查结果是确定的；若自然语言题目被错误形式化，即使证明通过，奖励仍然对应错误的命题。因此，检查器减少了证明判定噪声，不能消除数据和翻译错误。

**改进三：用通过检查的证明生成训练数据**

DeepSeek 自动生成了大量 Lean4 定理和证明，用于训练。生成的过程包括：

- 用 LLM 从自然语言数学题生成 Lean4 命题
- 用证明模型递归解决子目标
- 把找到的证明作为训练数据

### 3.2 Prover-V2 的成绩

论文报告 671B 模型在 MiniF2F-test 上用 Pass@32 达到 82.4%，把候选预算提高到 Pass@8192 时达到 88.9%；它还解决 PutnamBench 658 题中的 47 题。这里的候选数量差异非常大，88.9% 不能当作单次证明成功率。它说明增加形式证明搜索预算仍能覆盖更多题目，同时计算成本也随候选数上升。

## 4. 形式化验证可以用到哪里

形式检查把“判断步骤是否正确”变得更可靠，却没有让所有问题自动形式化。应用前要依次检查：任务能否写出精确定义，感知或自然语言输入能否可靠翻译，证明搜索成本是否可以接受。

形式化 PRM 的反馈更确定，但应用它需要满足以下条件：

### 4.1 领域受限

Lean4 主要用于数学。其他领域：

- **代码逻辑**：可以使用 Dafny、F\*、Coq 等工具，但需要先写出规格和不变量
- **自然语言推理**：只有部分任务能够转成逻辑约束，开放问题难以完整形式化
- **多模态推理**：感知结果本身带有不确定性，通常只能形式化其中的符号推理部分

因此，当前覆盖最好的是数学证明和具有明确规格的程序验证；开放语言任务只能形式化其中边界清楚的部分。

### 4.2 形式化数据稀缺

Lean4 语料和定理库远小于通用自然语言语料，而且“代码行”与“文本 token”也不能直接换算。模型能够学习的 tactic、库接口和证明模式因此更受数据覆盖限制，容易在语法、定理检索和证明搜索上失败。自动形式化质量与检查成本又进一步限制了可覆盖的题目。

### 4.3 翻译成本

形式化 PRM 要求把任务翻译成 Lean4。一处量词或类型翻译错误，就可能让检查器证明一个与原题不同的命题。可靠系统需要保留自然语言与形式命题的对应关系，并由人工、测试或另一套翻译检查发现语义偏差。

### 4.4 训练成本

证明搜索会反复生成 tactic 并调用 Lean 检查，分支数和证明深度一大，检查次数就会迅速增加。实际成本取决于缓存、并行度、定理库和搜索预算；公开资料不足以用一个固定倍数概括所有系统。

### 4.5 怎样扩大形式检查的覆盖范围

扩大覆盖范围需要分别解决输入翻译、证明生成和领域规格三个问题。

#### 自动形式化

让 LLM 学会把自然语言自动翻译成 Lean4。这是 [AlphaProof 的形式化器](https://deepmind.google/discover/blog/ai-solves-imo-problems-at-silver-medal-level/) 和 [Autoformalization with Large Language Models](https://arxiv.org/abs/2205.12615) 等研究的方向。

#### Lean4 与 LLM 混合

一种折中方式是让 LLM 先提出自然语言思路，再把其中可形式化的关键引理翻译成 Lean4 检查。未被形式化的步骤仍需单独评估，不能因为部分引理通过就把整条自然语言推理视为已证明。

#### 扩展到其他领域

代码可以使用 Dafny、F\* 等工具检查规格和不变量；物理与生物任务只有在对象、假设和规则能够精确定义时，才能交给形式系统。感知数据和开放语义仍需概率模型或人工判断。

#### 神经符号集成

语言模型负责提出引理和候选步骤，形式系统负责检查规则。两者之间必须保留失败信息：哪个 tactic 不合法、哪个子目标未解决、自然语言命题是否翻译一致。只有“生成—检查—修正”闭环完整，形式反馈才能指导下一次搜索。

## 小结

形式化 PRM 使用 Lean4 等系统检查候选证明。AlphaProof 和 DeepSeek-Prover-V2 说明，语言模型可以负责提出候选与搜索方向，证明检查器负责验证形式规则。

形式反馈的边界也很清楚：Lean 数据远少于自然语言语料，自动形式化可能改变题意，证明搜索又需要大量候选。它适合规则精确的任务，不能直接替代开放语言任务中的结果奖励或模型评价。

至此，我们看完了 PRM 的三条路线：

- **判别式 PRM**（17.2）：标注成本高，但推理成本较低
- **生成式 PRM**（17.3）：能够解释判断依据，但依赖评价模型的能力
- **形式化 PRM**（17.4）：反馈确定，但只覆盖能够形式化的任务
