# 16.6 推理链的展示与对齐

16.5 节让模型自行决定推理深度。假设模型内部尝试了三种方案，其中两种错误、一种正确，还夹杂重复计算和工具返回。最终回答应该把这些原始内容全部展示出来，还是整理成一段用户可以核查的解释？

这里必须区分三个对象：模型用于继续生成的内部推理、系统记录的执行轨迹、面向用户的解释。三者可以重合，也可以分别处理。隐藏内部 CoT 能保护训练资产并增加安全处理空间，可见推理则便于检查和复现；无论选择哪一种，展示出来的文字都不能自动证明模型按这条路径得到答案。

本节先解释隐藏与展示分别解决什么问题，再比较产品策略，最后讨论怎样监督中间过程与最终行为保持一致。

## 1. 为什么隐藏推理链

先从原始推理轨迹的特点出发。它可能包含未完成假设、被放弃的路径和敏感工具信息，长度也远超用户需要的解释。因此，“隐藏”不只是界面开关，还涉及数据资产、后处理和访问权限。

OpenAI 的 o1 不直接返回内部 CoT，用户获得的是最终答案或整理后的说明。这个设计主要涉及训练资产、安全处理和产品可读性三个问题。

### 1.1 防止推理数据被直接蒸馏

连续收集模型生成的推理轨迹，可以形成用于蒸馏的数据集。服务提供方因此可能把内部轨迹视为训练资产，只提供摘要或最终答案。具体商业权衡通常不会在公开材料中完整披露。

开放权重模型通常更愿意提供可用于复现和微调的推理数据，闭源服务则更强调内部轨迹保护。两种选择也会影响用户能否检查步骤和研究者能否复现实验。

### 1.2 在推理链与答案之间加入安全处理

原始轨迹可能复述敏感输入、工具返回或未采用的危险方案。若这些内容直接进入用户界面，就绕过了最终回答层的编辑与过滤。把内部轨迹和用户输出分开，可以在返回结果以前执行脱敏、权限检查和安全策略；工具动作仍要在执行接口单独校验。

### 1.3 控制用户看到的信息量

原始推理轨迹可能很长、包含重复尝试，也未必适合作为解释。产品可以把它整理成简短依据，但摘要会丢失部分过程信息，需要靠引用、计算或外部验证补充。

医疗、法律和金融等高风险场景确实需要可审计依据，但原始 CoT 不是充分证据。更可靠的交付包括引用来源、可重复计算、适用条件和不确定性说明；这些内容可以由系统从内部轨迹整理，也可以独立生成并验证。

### 1.4 Hidden CoT 的工程实现

一种常见的数据流是：

1. 模型生成完整 CoT + 答案
2. 后处理：剥离 CoT 部分，只保留答案
3. （可选）生成一个"用户友好的总结"代替原始 CoT

Reasoning summary 用经过整理的依据替代原始轨迹。它减少重复和敏感内容，但也可能遗漏关键步骤，因此仍要检查摘要中的引用、计算和结论是否对应最终答案。

## 2. 为什么展示推理链

隐藏原始轨迹减少了暴露，却把检查责任留给服务提供方。开放模型和研究场景更希望读者看到推导、复现实验并定位错误，这形成了展示推理内容的另一条路线。

[DeepSeek-R1](https://arxiv.org/abs/2501.12948) 采用可见推理输出，用户可以在最终答案以前看到模型生成的推理内容。可见文本仍是模型输出，不能自动视为忠实记录或正确证明。

### 2.1 开源生态建设

DeepSeek-R1 发布了模型权重和蒸馏模型，例如 [DeepSeek-R1-Distill-Qwen-32B](https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Qwen-32B)。可见推理输出还让开发者能够收集案例、分析失败并训练自己的学生模型。开放带来复现价值，也意味着推理数据更容易被再次使用。

### 2.2 检查推理步骤

Visible CoT 为用户提供三种检查入口：

- 检查推理步骤是否正确
- 发现模型的推理错误
- 学习模型如何解题（教育场景）

### 2.3 学术透明度

公开推理样例使研究者能够比较不同训练阶段的长度、自检和错误模式。它提高了可观察性，但研究结论仍要结合模型输出、工具日志和最终评测，不能把一段 CoT 当作内部机制的完整记录。

### 2.4 Visible CoT 的代价

Visible CoT 也有代价：

- **数据复用**：公开轨迹可以被用于蒸馏和再训练。
- **内容暴露**：轨迹可能包含敏感输入、错误方案或工具细节，需要和最终回答一样接受安全处理。
- **阅读成本**：长轨迹包含大量尝试，界面通常需要折叠、摘要或只展示关键依据。

## 3. 不同展示策略如何选择

隐藏和展示并非只有两个极端。系统可以保留内部轨迹，只对用户返回结构化摘要；也可以公开可读推导，同时隐藏安全敏感的工具细节。选择策略时应分别考虑谁需要检查、检查什么，以及错误内容暴露后有什么影响。

产品大致采用三种输出粒度：

| 输出方式     | 用户看到什么             | 主要收益                     | 仍需解决的问题                   |
| ------------ | ------------------------ | ---------------------------- | -------------------------------- |
| 隐藏原始推理 | 最终答案                 | 输出简短，内部轨迹不直接暴露 | 外部难以检查中间过程             |
| 推理摘要     | 关键依据与最终答案       | 兼顾可读性和部分检查         | 摘要可能遗漏或改写关键步骤       |
| 可见推理     | 模型生成的推理文本与答案 | 便于复现、教学和错误分析     | 内容未必忠实，也可能包含敏感信息 |

具体产品接口会变化，判断时应直接检查它返回的是原始轨迹、经过处理的摘要，还是为用户重新生成的解释。

## 4. 如何对齐并监督推理过程

决定展示范围以后，仍未解决“中间过程是否可靠”。可见 CoT 可能写得合理却与真实计算无关，隐藏 CoT 也可能包含与最终行为冲突的计划。过程对齐关注的是中间状态、工具动作与最终结果之间能否相互验证。

传统偏好数据主要评价最终回答。推理模型还生成较长的中间文本，这些内容会影响后续 token 和工具动作，即使最终不向用户展示，也需要纳入训练与监控。

### 4.1 推理链是否需要价值约束

安全目标应覆盖最终文本、工具动作和可访问日志。内部推理中出现一个被放弃的危险候选，并不会自动造成外部行为；当它被返回给用户、写入可访问日志，或驱动工具执行时，风险才进入系统边界。因此需要在三个位置分别控制：训练时减少不安全轨迹，执行时限制工具权限，输出时过滤敏感内容。

### 4.2 推理链与最终答案可能不一致

[相关研究](https://arxiv.org/abs/2511.18397)会比较模型生成的中间文本与最终行为是否一致。例如，中间文本可能提出一种方案，最终答案却采用另一种方案；也可能写出符合规范的解释，但工具日志显示执行了不同动作。

若内部推理不可见，用户无法直接比较中间文本与最终回答。不过，CoT 也不等同于模型的“真实想法”；研究对象是可观察文本、隐藏激活和最终行为之间是否一致。检测这种差距需要受控探针、行为评测和工具日志。

### 4.3 隐藏触发器与 Sleeper Agents

[Anthropic 的 Sleeper Agents 研究](https://www.anthropic.com/news/sleeper-agents-training-deceptive-llms-that-persist-through-safety-training)（2024）研究了模型在特定触发条件下改变行为的情形。检测重点是输入条件、内部激活、生成文本和实际动作之间的变化，不能假设触发器一定会在可见 CoT 中直接写出来。

可见推理为人工检查提供了一条线索，攻击者也可能故意隐藏触发行为。隐藏推理则需要服务方使用内部监控和外部行为测试。两种方案都不能只靠“看一眼 CoT”完成安全判断。

### 4.4 推理对齐的研究方向

过程监督可以放在四个不同位置：

#### 过程奖励对齐

对中间步骤增加正确性或安全标签，再用 [第 17 章 PRM](../chapter20_prm_search/outcome-vs-process) 训练评价器。它适合可切分、可判断的推理或工具步骤。

#### CoT 监控

让独立监控模型读取推理文本和工具日志，标记规则冲突、异常权限请求或结论不一致。监控模型也会犯错，因此要用人工抽查和对抗样本评测。

#### 可解释性工具

机械可解释性尝试分析隐藏激活，例如用 SAE（Sparse Autoencoders）寻找与某些概念相关的方向。它观察的是模型内部表示，与检查生成文本提供不同证据。

#### 宪法式推理

把原则拆成判断准则和偏好样本，在训练阶段提高符合准则的推理与回答概率。规则还要落到可测试行为上，否则很难判断模型是否遵守。

### 4.5 比较 Hidden CoT 与 Visible CoT

Hidden CoT 与 Visible CoT 需要在以下目标之间取舍：

| 目标         | 隐藏原始推理               | 展示推理文本                               |
| ------------ | -------------------------- | ------------------------------------------ |
| 训练资产保护 | 轨迹较难被直接收集         | 轨迹更容易被复用和蒸馏                     |
| 外部检查     | 依赖摘要、引用和服务方日志 | 用户可以检查文本步骤，但仍需验证忠实性     |
| 内容安全     | 返回前可以统一处理         | 展示内容本身也要接受安全过滤               |
| 教学与复现   | 需要另行生成可读解释       | 更方便观察方法与错误样例                   |
| 内部监控     | 服务方可使用完整轨迹       | 公开文本只覆盖可见部分，仍可能缺少隐藏状态 |

Visible CoT 便于检查和教学，也更容易暴露敏感内容或被用于蒸馏；Hidden CoT 便于保护内部推理并统一安全处理，却降低了外部审查能力。推理摘要提供了中间方案，但摘要本身仍需验证是否忠实反映模型的决策依据。

## 小结

第 16 章从可验证奖励出发，依次讨论纯 RL、推理计算、模式切换、自适应预算和推理链展示。它们连成同一条因果线：RL 让较长推理稳定出现，额外推理计算提高复杂任务的成功率，预算控制负责约束成本，过程可见性决定系统能够怎样接受外部检查。

推理链是否展示和推理过程是否正确是两个不同问题。[第 17 章过程奖励与推理时搜索](../chapter20_prm_search/outcome-vs-process) 将进一步说明怎样对中间步骤提供反馈，并在推理时用这些反馈选择路径。
